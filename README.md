# 实验验证两种编码说关于表象的论证 · 网页版大小判断任务

**设计与实现：** 赵钰涛（认知心理学课程作业）  
本仓库为独立完成的行为实验程序：从试次设计、刺激呈现、反应时采集、数据质检到远端存储与导出，均在本项目中实现与联调，便于老师检阅。

---

## 一、实验在做什么

被试在屏幕左右看到一对刺激（**实物图片**或**文字名称**），在**真实世界体积**意义上判断哪一侧更大，用键盘 **← / →** 尽快作答。图画与文字各有一致 / 不一致两种呈现方式（共四条件），用于在知觉冲突下考查大小判断与内在表征过程。正式阶段包含 **80** 个分析用试次与 **20** 个文字填充试次（不计入分析），并在第 **30、60** 个正式试次后插入注意力检查。

材料说明（简笔画预实验 → 正式采用实物图）见网页内 **「材料核对」** 页。

## 二、技术实现要点（对应源码文件）

| 模块 | 文件 | 职责摘要 |
|------|------|----------|
| 实验参数与词表 | `js/experiment-parameters.js` | 计时、练习/正式词对、四条件呈现规格、Supabase 连接项；**唯一配置源**。 |
| 云端会话同步 | `js/supabase-session-sync.js` | PostgREST 上传 / 拉取整段会话 JSON，供多终端汇总数据。 |
| 试次序列 | `js/trial-sequence-builder.js` | 练习与正式 100 试次的构造：块拉丁方、同对最小间隔、左右平衡、可复现随机种子。 |
| 本地存档与导出 | `js/session-save-export.js` | `localStorage` 持久化、试次级 CSV、多会话总览 CSV、JSON 导出。 |
| 统计与质检 | `js/session-quality-stats.js` | 按条件聚合 RT/正确率、会话完整性标记，供结束页与数据页使用。 |
| 界面与流程 | `js/run-experiment-ui.js` | 多屏状态机、键盘采集、材料预加载、材料核对与数据面板刷新逻辑。 |
| 样式 | `css/style.css` | 布局与试次呈现区、仪表盘等视觉规范。 |
| 数据库脚本 | `supabase-setup.sql` | 建表、RLS 策略、`anon` 表级授权（解决拉取列表时的权限问题）。 |

页面入口：`index.html`。脚本 **加载顺序不可打乱**（见 `index.html` 底部注释）。

## 四、本地运行

```bash
cd size_judge_lab
python -m http.server 8080
```

浏览器访问 `http://127.0.0.1:8080/`（**勿**用 `file://` 打开，否则部分能力受限）。Windows 也可双击 `start_server.bat`。

## 五、刺激材料与预加载

- **实物图**：已全部置于 `stimuli/` 目录，文件名与 `experiment-parameters.js` 中 `PRACTICE_PAIRS`、`PAIRS` 的 `bigFile` / `smallFile` 一一对应；扩展名由 `IMAGE_EXT`（默认 `.png`）指定。  
- **填充试次**：仅为文字呈现，不依赖额外物体图片。  
- **预加载**：被试点击「开始新会话」后，程序根据当前正式 80 试与练习试次中所有**图画**试次收集 URL，在后台预加载图片；全部成功后再进入指导语页。若有失败，状态行提示数量，试次中对应格可为空白，可在「材料核对」核对文件名与文件是否存在。  
- **部署**：图片路径为相对 `index.html` 的 `stimuli/...`，将仓库以 **根目录即站点根** 部署到 GitHub Pages 时无需再配子路径。

## 六、数据、隐私与部署说明

- **远端：** 在 `experiment-parameters.js` 的 `REMOTE` 中填写 Supabase 项目 URL 与 anon key，并执行 `supabase-setup.sql`。公开仓库提交密钥存在被他人滥用的风险，课程展示可接受时请自行评估；更稳妥做法是私有仓库或轮换密钥。  
- **本地：** 上传失败时会回退写入本机 `localStorage`；「数据」页为远端与本机记录的合并视图。  
- **GitHub Pages：** 仓库 **Settings → Pages** 选择 `main` 分支、`/(root)` 部署；站点地址一般为 `https://<用户名>.github.io/<仓库名>/`。

## 七、试次结构与数据处理逻辑（摘要）

### 7.1 会话与标识

- 每次「开始新会话」生成唯一 `sessionId`（优先 `crypto.randomUUID()`）与可读 `subjectId`，并采样 `sessionSeed`（32 位无符号整数）驱动后续所有伪随机过程，保证**同种子可复现**同一试次序列结构（仍保留被试反应为随机变量）。

### 7.2 练习阶段

- 仅 **图画一致 / 图画不一致** 两条件，词对与正式实验不同；练习试次数为配置中的固定序列。  
- 每轮练习结束后计算正确率；达到 `PRACTICE_MIN_ACC` 方可进入正式，否则可再练，受 `PRACTICE_MAX_TRIES` 上限约束（具体分支见界面逻辑）。

### 7.3 正式主流程（100 试次）

- **80 个正式分析试次**：20 个词对 × 4 条件（图画/文字 × 一致/不一致）。条件在试次流中以 **4 试为一组块** 排列，块内顺序由拉丁方思想与 `subjectIndexForLatin` 共同约束；同一词对在流中再次出现须间隔不少于 `MIN_OTHER_TRIALS_BETWEEN_SAME_PAIR`；真实更大侧在左/右平衡。  
- **20 个填充试次**：均为**文字**试次，按「每 4 个正式试次后插入 1 个填充」的规则嵌入序列；字段 `phase: "filler"`，`includeInAnalysis: 0`，在聚合与导出分析用指标时**一律排除**。  
- **注意力检查**：在主流程中累计完成第 30、第 60 个**正式**（非填充）试次后各插入一次；反应记入 `session.attention`，用于数据质检。

### 7.4 反应时与按键

- 试次从注视点呈现结束、刺激可见起计时，至有效按键或超时止；时间戳使用 `performance.now()`，单位为毫秒。  
- 仅接受 **← / →** 作为有效反应；超时记 `timedOut: true`，在条件聚合与 CSV 分析中可与业务规则一致地排除或单独统计。

### 7.5 统计与导出

- **条件内聚合**（`session-quality-stats.js`）：仅针对 `phase === "formal"` 且 `includeInAnalysis === 1` 的试次，按 `conditionKey` 分四条件计算 n、正确率、均值/中位数 RT（可排除超时试次参与 RT 统计，与实现一致）。  
- **会话完整性**（`sessionQuality`）：检查主流程条数是否为 100、正式 80、填充 20、注意力检查是否已记录等，供数据页「待审核」展示。  
- **导出**：试次级 CSV 由 `session-save-export.js` 展开试次日志；多会话总览 CSV 在会话粒度上合并质量标记与各条件平均 RT/正确率；JSON 为整段会话对象，便于存档或二次分析。
